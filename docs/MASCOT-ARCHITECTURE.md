# معماری مَسکات — از رویداد تا بدن

> یک صفحه برای کسی که باید این سیستم را نگه دارد. اگر می‌خواهی بدانی «چرا مسکات این کار را
> کرد»، از پایین به بالا بخوان. اگر می‌خواهی چیزی عوض کنی، از بالا به پایین.

---

## ۱. اصلِ واحد

```
رویداد (کاربر/صفحه/دکمه/AI)
        ↓
mascotController.dispatch(event)        ← تنها درِ ورودی
        ↓
دروازه‌ی اولویت → ماشین حالت → صفِ برنامه → یک زمان‌سنج
        ↓
{state, gaze, expression, laptop, scene}
        ↓              ↓
   mascotBus (بدن)   Laptop (صفحه‌نمایش)
        ↓
   MascotWorkstation (صحنه)
```

**هیچ ماژولی حق ندارد مستقیماً انیمیشن اجرا کند.** اگر جایی دیدی که چت یا یک دکمه دارد
`mascot.scene(...)` صدا می‌زند، آن یک باگ است — باید `dispatch` کند.

| فایل | نقش | چی را نباید اینجا گذاشت |
|---|---|---|
| `soul.ts` | کنترل‌گر: ماشین حالت، اولویت، صف، زمان‌سنج، watchdog، اعتبارسنجی خروجی AI | انتخابِ فریم، CSS |
| `mascotBus.ts` | بدن: فقط شمارنده‌ی فریم صحنه‌ها | تصمیم‌گیریِ رفتاری |
| `rig.ts` | لنگر و مقیاس هر فریم + هندسه‌ی صحنه | منطقِ زمان‌دار |
| `MascotWorkstation.tsx` | صحنه: بدن + لپ‌تاپ + دست‌ها + نگاه | حالت (state) |
| `Laptop.tsx` | لپ‌تاپِ وضعیت‌مند | — |
| `useMascotEvents.ts` | زندگیِ اجتماعیِ کاراکتر (چه بگوید) | انیمیشن |

---

## ۲. اولویت‌ها

```
IDLE(0) < LOW(1) < NORMAL(2) < HIGH(3) < CRITICAL(4)
```

هر رویداد اولویتِ پیش‌فرض خودش را دارد (`EVENT_PRIORITY`) و هر حالت با اولویتش از خودش
دفاع می‌کند (`STATE_PRIORITY`). قانون:

- اولویتِ رویداد **بیشتر** از حالتِ فعلی → فوراً قبول.
- **کمتر** → دور انداخته می‌شود (برای همین حرف‌های محیطی هرگز کارِ AI را قطع نمی‌کنند).
- **مساوی** → باید حداقلِ زمانِ حالت (`MIN_STATE_HOLD` / `MIN_WORKING_HOLD`) گذشته باشد؛
  وگرنه رویداد **به تعویق می‌افتد، نه دور انداخته می‌شود** (`defer`).
  این نکته مهم است: دور انداختنِ `AI_REQUEST_COMPLETED` دقیقاً همان باگی بود که مسکات را
  تا ابد در حالتِ WORKING نگه می‌داشت.

یک watchdog هم هست: اگر حالتی غیر از IDLE بیش از ۹۰ ثانیه بماند و درخواستی واقعاً باز
نباشد، کنترل‌گر خودش به IDLE برمی‌گردد.

## ۳. چرخه‌ی عمرِ واقعی (هیچ زمانِ ساختگی‌ای اینجا نیست)

```
CHAT_MESSAGE_SENT ─┐
                   ├─→ WORKING ── AI_REQUEST_COMPLETED ─→ READING → REACTING → IDLE
AI_REQUEST_STARTED ┘                    │
        ↑                               └─ AI_REQUEST_FAILED/CANCELLED → ERROR → IDLE
   AI_REQUEST_STREAMING (فقط throttled؛ هیچ stateای عوض نمی‌شود)
```

- `WORKING` فقط با پایان یا شکستِ **واقعی** تمام می‌شود؛ نه با تایمر.
- برای درخواستِ طولانی، `startMicro()` زیر-اکت‌ها را عوض می‌کند (تایپ → مکث → نگاه به
  صفحه → فکر) ولی **حالت** همان WORKING می‌ماند. پس یک جوابِ ۵۰۰ میلی‌ثانیه‌ای کوتاه است
  و یک جوابِ ۲۵ ثانیه‌ای تا آخر زنده می‌ماند.
- طولِ «خواندن و واکنش» از **طولِ واقعیِ جواب** می‌آید (`scaledHold`)، سقف دارد، و حداقلش
  چند صد میلی‌ثانیه است.

## ۴. قراردادِ AI (واژگانِ بسته)

مدل فقط می‌تواند این‌ها را بفرستد:

```
[[act: {"action":"REACTING","gaze":"USER","expression":"NEUTRAL","bubble":"..."}]]
```

- `action`: `IDLE | LOOK_AT_USER | LOOK_AT_LAPTOP | WORKING | TYPING | THINKING |
  READING | REACTING | WAITING | RETURN_TO_IDLE`
- `gaze`: `USER | LAPTOP_SCREEN | KEYBOARD | CHAT | ENVIRONMENT`
- `expression`: `NEUTRAL | FOCUSED | PLEASED | CONCERNED | CURIOUS | PROUD | TIRED`

`parseMascotIntent` هر چیزِ دیگر را **`null`** برمی‌گرداند و `applyAIRawAnswer` در آن صورت
به یک واکنشِ امن (`REACTING`/`NEUTRAL`) برمی‌گردد — پاسخ نمایش داده می‌شود، چت نمی‌شکند.
واژگانِ قدیمیِ `pose` فعلاً پذیرفته می‌شود (`POSE_TO_ACTION`) تا ورکر و فالبکِ محلی همگام
بمانند.

> اگر خواستی واژگانی اضافه کنی، آن را به `MASCOT_ACTIONS` در `soul.ts` **و** به `ACT_GUIDE`
> در `functions/api/chat.ts` اضافه کن — وگرنه مدل چیزی می‌فرستد که کلی‌نت رد می‌کند.

## ۵. ریگ (`rig.ts`) — چرا بدن نمی‌پرد

فریم‌ها همگی روی یک کانواسِ ۶۴۰×۶۹۸ هستند، اما با دوربین‌های متفاوت صادر شده‌اند:

| | کمینه | بیشینه |
|---|---|---|
| مرکزِ سر | ۰.۳۷۵ | ۰.۶۲۵ |
| خطِ مو | ۰.۰۱۴ | ۰.۱۹۹ |
| پهنای صورت | ۰.۱۸۶ | ۰.۳۱۴ |

هر فریم با یک تبدیلِ `scale + translate` طوری جابه‌جا می‌شود که **مرکزِ سر و خطِ مو روی یک
لنگرِ ثابت** بنشینند (`headAnchorX/Y`). پهنای صورت مقیاس را تعیین می‌کند، چون از همهٔ
اندازه‌های دیگر کمتر به حالت/چرخشِ سر حساس است (پهنای silhouette را حجمِ مو خراب می‌کند،
و ارتفاعِ تنه را محلِ برش).

اگر خواستی این اعداد را دوباره اندازه بگیری یا فریمِ جدیدی اضافه کنی:
۱. بایت‌های آلفا را بخوان، ۲. مرکزِ بزرگ‌ترین تکه‌ی رنگِ پوست در ۴۵٪ بالایی را به‌عنوانِ
`headCx` بگیر، ۳. اولین ردیفِ مات را به‌عنوانِ `headTop`، ۴. پهنای آن تکه را `faceW`.
اسکریپت‌های تحلیلی که با آن‌ها این اعداد به دست آمد در تاریخچه‌ی این کار هستند — در صورت
نیاز دوباره نوشته می‌شوند.

## ۶. صحنه و ترتیبِ لایه‌ها

```
z0  mws-ambient   نورِ اتاق
z1  mws-desk      سطحِ میز
z2  mws-figure    بدن (نگاه + ریگ + نفس کشیدن)
z3  mws-deck      صفحه‌کلید — برشِ کمرِ اسپرایت را می‌پوشاند
z4  mws-hands     دست‌ها (بیرون کشیده‌شده از فریم‌های تایپ)
z5  mws-lid       درِ لپ‌تاپ — سینه و مچِ دست را می‌پوشاند
```

دو نکته‌ی فیزیکی که این ترتیب را تعیین می‌کنند:

- **deck بعد از بدن**: اسپرایت‌ها نیم‌تنه‌هایی‌اند که از کمر بریده شده‌اند؛ صفحه‌کلید است که
  این برش را پنهان می‌کند.
- **lid بعد از دست‌ها**: مچ باید پشتِ صفحه پنهان شود، درست مثل آدمی که از روبه‌رو-بالا دارد
  تایپ می‌کند.

دست‌ها یک داراییِ جداگانه‌اند (`public/mascot/hands-{1,2,3}.webp`) که با ماسکِ رنگِ پوست از
فریم‌های تایپ بیرون کشیده شده‌اند. جایشان با `handsRig()` روی کلیدها ثابت می‌شود و مستقل از
مقیاسِ فریم است.

اگر خواستی فریمِ جدیدی اضافه کنی: در `FRAMES` ثبتش کن، و اگر دست‌هایش روی میز است
`deskHands: true` بگذار (وگرنه وقتی آن فریم پخش می‌شود دست‌ها غیب می‌شوند).

## ۷. نگاه

`MascotWorkstation` یک حلقه‌ی rAFِ **مشترک** دارد (یکی برای همهٔ نمونه‌های صفحه). کنترل‌گر
فقط هدف را می‌گوید (`snapshot.gaze`)؛ حلقه یک بردارِ واحد تولید می‌کند و CSS آن را به
چرخش/خم‌شدن تبدیل می‌کند (`.mws-figure`). دامنه در CSS است تا بشود در بریک‌پوینت‌ها کمش کرد.

- `ENVIRONMENT` یک ناحیه‌ی مرده دارد → یعنی واقعاً **ساکن** می‌ماند، نه اینکه مدام بلرزد.
- `prefers-reduced-motion` → بدونِ easing، بدونِ نفس‌کشیدن، بدونِ انیمیشنِ صفحه.

## ۸. تست

```bash
npm run test:mascot     # ۲۲ سناریوی رفتاری، با تایمرهای واقعی
npm run lint            # همان tsc --noEmit
npm run build
```

اسکریپت در `scripts/mascot-scenarios.ts` است. وقتی رفتاری عوض می‌کنی، سناریوی متناظرش را
هم عوض کن — این فایل قرار است جلوی برگشتِ باگ‌هایی را بگیرد که یک‌بار اتفاق افتاده‌اند
(گیر کردن در WORKING، تلاطمِ استریم، قطع شدنِ کار توسط حرف‌های محیطی، دستورِ نامعتبرِ AI).
